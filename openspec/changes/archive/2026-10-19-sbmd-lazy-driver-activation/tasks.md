## 1. SbmdDriver: split claim metadata from active registration

- [x] 1.1 Keep the claim metadata (name, `matter.deviceTypes`, `vendorId`, `productId`, device class, `filePath`) resident on `SbmdDriver`'s `SbmdRegistration` in every state; while inactive the registration is reduced to just those claim fields (no separate stub type). The claim-time accessors read the immutable spec snapshot instead (task 3.1).
- [x] 1.2 Change `SbmdDriver::Activate()` to read the spec content from `filePath` on disk once the in-memory `source` has been released (re-using `source` only while it is still retained), parse, build the full `SbmdRegistration` and dispatch tables, and root handler JSValues; fail activation cleanly (log, return false) on file read/parse error.
- [x] 1.3 Change `SbmdDriver::Deactivate()` to additionally release the `source` string and the heavy `SbmdRegistration` collections (endpoints, resources, aliases, handlers) back to the claim-metadata state, in addition to releasing GC roots and clearing dispatch tables.
- [x] 1.4 Stop retaining `source` after load; ensure the claim metadata is the only resident state while inactive. Keep `Activate()`/`Deactivate()` idempotent.
- [x] 1.5 On activation, validate the re-read spec's claim-identity fields (name, device types, vendor/product IDs, device class) against the claim metadata; on mismatch (or read/parse failure) fail activation, log, and abort the bind.
- [x] 1.6 Update `SbmdDriverTest.cpp`: assert claim metadata is available while inactive; assert `source`/registration are released after deactivation; assert activation re-reads from disk; add a deactivate→reactivate round-trip test. (unit)

## 4. MatterDeviceDriver: deactivate on last-device removal

- [x] 4.1 Add a protected virtual hook (e.g. `OnLastDeviceRemoved()`) to `MatterDeviceDriver`, invoked from `DeviceRemoved` after erasing the device under `devicesMutex` when the `devices` map becomes empty; base default is a no-op.
- [x] 4.2 Override the hook in `SpecBasedMatterDeviceDriver` to `Deactivate()` the driver under the JS mutex; ensure outstanding deferred operations for the removed device are settled/cancelled before deactivation. Serialize the whole activation lifecycle: the re-read spec is validated against the cached versions before it is committed (so a concurrent binder never adopts an unvalidated registration); a per-driver in-flight-bind counter is held across the whole of `AddDevice`; and last-device teardown and bind rollback share one `DeactivateIfIdle()` primitive that deactivates only when the driver is still activated, no bind is in flight, and the device map is still empty when rechecked under `devicesMutex`. This closes the stale-empty-map race, stops a failed bind's rollback from shedding a concurrently-adopted activation, and retries a teardown that was deferred while a bind was racing. The claim-time accessors read the immutable spec snapshot taken at construction (task 4.6), never the registration object that `Activate()` swaps. Because report dispatch reads the registration and dispatch tables on the Matter event loop without the JS mutex, every step that replaces or frees them (committing an activation, failed-bind teardown) runs under `Matter::RunWithStackLock()`, which holds the CHIP stack lock that the event loop holds while dispatching, or runs directly on the event loop thread or when that thread does not exist (see design D5). Activation loads and validates the spec before taking that lock, so a mismatched spec is never committed.
- [x] 4.3 Verify the driver stays active while any device remains and deactivates only on the last removal (per-driver count). (unit) — covered at integration level: `sbmd_lazy_activation_test.py::test_removal_deactivates_driver` commissions then removes a device (via `client.remove_device`) and asserts the deactivation counter increments and the active-count gauge returns to zero.
- [x] 4.4 Add unit coverage for the last-device-removed → deactivate path and multi-device stay-active path. (unit) — last-device-removed path covered by `test_removal_deactivates_driver`; multi-device stay-active path covered by `test_driver_stays_active_until_last_device_removed`; `SbmdDriverTest` covers the `Deactivate` state shedding.
- [x] 4.5 Cover deferred-operation settlement on last-device removal: a pending deferred op is failed/settled and the driver deactivated, and a late response is handled safely. (integration) — `sbmd_lazy_activation_test.py::test_deferred_op_settled_when_last_device_removed` withholds the device's command response (via the `armToggleHang`/`releaseToggle` side-band on `DeferredCmdTestDevice`), removes the device while the op is parked, and asserts the blocked caller returns **with a failure result (`ok=False`)**, the driver deactivates, and Barton stays healthy after a late response.
- [x] 4.6 Reject a bind whose re-read spec changed the device-class version, an endpoint profile version, or the set of endpoint profiles (versions published to the device-service layer at construction for commissioning/reconfiguration). — implemented in `SbmdDriver::LoadForActivation()` (`VersionMismatch`, checked against the `SpecSnapshot` the constructor takes, alongside the claim-identity check, before the registration is committed), which compares the complete snapshot and re-read profile sets so a removed profile cannot leave a stale cached version (out-of-range numeric fields are rejected earlier at parse time, see task 4.8); covered by `SbmdDriverTest::ActivateRejectsChangedDeviceClassVersion`, `::ActivateRejectsChangedProfileVersion`, `::ActivateRejectsChangedProfileSet`, `::ActivateAcceptsEditsThatKeepVersions`, and `::ActivateAcceptsReorderedProfiles`, and by `sbmd_lazy_activation_test.py::test_bind_rejected_when_device_class_version_changes`, `::test_bind_rejected_when_profile_version_changes`, and `::test_bind_rejected_when_profile_set_changes` (renaming the endpoint profile removes the cached profile from the re-read set) — each patches an isolated per-test copy of the spec on disk (via the `isolated_sbmd_default_environment` fixture, so the checked-in resources are never mutated), commissions with a short per-attempt timeout (so both commissioning phases finish inside the restore window), and asserts the device is not added, the active-driver gauge stays zero, and the `sbmd.driver.activation.failure{reason=version_mismatch}` counter increments; normal commissioning (unchanged versions) is unaffected, verified by the rest of the integration suite.
- [x] 4.7 Deterministically exercise the in-flight-bind lifecycle guard. (unit) — `SbmdLifecycleTest.cpp::SbmdLifecycleGuardTest` drives the guard's state directly through the friended `TestableSpecBasedMatterDeviceDriver` (no threads, no barrier, no production test seam): `TeardownDeferredWhileBindInFlightThenRetriedWhenIdle` marks a bind in flight (`bindsInProgress`), fires `OnLastDeviceRemoved` and asserts the driver stays active, then clears the counter and asserts `DeactivateIfIdle` retries the teardown; `DeactivateIfIdleIsNoOpWhileDeviceBound` binds a resolvable device through the real `AddDevice` and asserts `DeactivateIfIdle` is a no-op while a device remains. `AddDevice` brackets itself with the `InFlightBind` RAII guard, so pinning the guard's contract plus the real bind path covers the protocol without shipping a test seam.
- [x] 4.8 Reject numeric claim/version fields that are not integers within range at parse, so a disk edit cannot wrap, narrow, truncate, or coerce into an aliasing value (`SbmdLoader` requires `matter.deviceTypes`/`vendorId`/`productId` to be integers in 0–`0xFFFF` and `barton.deviceClassVersion`/endpoint `profileVersion` integers in 0–255; anything else, including fractional, `NaN`/infinite, string, boolean, and `null` values, is rejected and reported as `SbmdLoadFailure::InvalidField`). Covered by `SbmdDriverTest.cpp` (`ProfileVersionAboveUint8Rejected`, `ProfileVersionWraparoundRejected`, `DeviceTypeAboveUint16Rejected`, `VendorIdAboveUint16Rejected`, `DeviceClassVersionAboveUint8Rejected`, `Uint16AndUint8BoundaryValuesAccepted`, `NonIntegerNumericFieldsRejectedAsInvalidField`, `IntegralNumericFieldsAccepted`, `LoadFailureDistinguishesInvalidFieldFromOtherErrors`).
